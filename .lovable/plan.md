# Full Migration to Lovable Cloud

Replace the custom Express server (`server.ts`) and JSON-file storage (`db_*.json`) with Lovable Cloud: Supabase Postgres tables, Row-Level Security, edge functions, and the Lovable AI Gateway. Remove `server.ts` entirely; the app becomes a pure Vite SPA.

## What changes for the user

- Identity becomes a real account. The current "User ID + Display Name" form becomes **email + password** sign-in/sign-up (Lovable Cloud default). Existing local-storage IDs will no longer log you in — first launch will show the sign-in screen.
- Leaderboard, history, community questions, and your profile score are stored in the cloud database and persist across devices.
- AI question generation switches from your Gemini key to the Lovable AI Gateway (no key setup needed).
- Online matchmaking (presence + invites + duel lobby) moves into the database. Polling intervals stay the same; behavior is preserved.

## Database schema

- `profiles` (id uuid PK = auth.users.id, display_name text unique, score int default 1000, rank text, created_at)
  - Auto-created via `handle_new_user` trigger on `auth.users` insert.
- `leaderboard` (id uuid, user_id uuid, name, score, streak, accuracy, mode, exam, created_at)
- `battle_history` (id, user_id, player, opponent, mode, score, streak, result, created_at)
- `community_questions` (id, author_id, subject, exam, question, options jsonb, correct_index, explanation, author, created_at)
- `online_presence` (user_id PK, name, score, rank, last_active timestamptz) — heartbeat row, rows older than 8s treated offline.
- `duel_invites` (lobby_id PK, sender_id, sender_name, receiver_id, exam, subject, custom_topic, status, num_questions, created_at)
- `duel_lobbies` (lobby_id PK, host_id, host_name, host_score, host_index, guest_id, guest_name, guest_score, guest_index, status, exam, subject, custom_topic, questions jsonb, rope_position int, host_consecutive_wrong, guest_consecutive_wrong, num_questions, winner_id, last_update)

RLS: read-all on leaderboard / history / community_questions / online_presence (public arena); write requires `auth.uid() = user_id`. Duel rows readable/writable only by host or guest.

## Edge functions

- `generate-questions` — calls Lovable AI Gateway (`google/gemini-3-flash-preview`) with the existing prompt + JSON schema via tool calling. Returns `{ questionSet, useFallback }`.
- `duel-sync` — replaces `/api/lobby/sync` and `/api/invites/respond` server-side logic (rope math, consecutive-wrong knockout, winner selection, question seeding from community + fallback bank). Runs with service role so both players can mutate the shared lobby row safely.
- `presence-tick` — accepts a heartbeat, upserts `online_presence`, returns active users + pending invites for the caller. Keeps presence logic atomic.

Leaderboard/history/community-question reads and inserts go directly through `supabase-js` (no edge function needed; RLS enforces safety).

## Client changes (`src/App.tsx`)

- Add an auth screen (email + password) replacing the current registration modal. `onAuthStateChange` listener set up before `getSession()`.
- Replace every `fetch("/api/...")` with either `supabase.from(...).select/insert` or `supabase.functions.invoke(...)`.
- Profile (`aspirantName`, `userScore`, `userRank`) is loaded from `profiles` after auth.
- Presence loop → `supabase.functions.invoke("presence-tick")`.
- Lobby loop → `supabase.functions.invoke("duel-sync")` (or direct row read + edge-function mutate).
- Invite send/respond → insert into `duel_invites` + invoke `duel-sync`.
- AI generation → `supabase.functions.invoke("generate-questions")`.

## Files removed

- `server.ts`, `db_users.json`, `db_leaderboard.json`, `db_history.json`, `db_questions.json` (community seeds are inserted into `community_questions` via the initial migration).
- `package.json` scripts updated to standard Vite (`vite` for dev, `vite build` for build). `express`, `@google/genai`, `dotenv` deps removed.

## Technical details

- Auth: email + password only on first pass (Google sign-in can be added later if requested).
- Polling intervals unchanged (presence 3.2s, lobby 1.2s).
- The 50-row leaderboard cap and 30-row history cap are preserved via SQL (sorted select + limit on read; periodic cleanup not required at this scale).
- Fail-limit math (`max(1, round(0.10 * numQuestions))`), rope ±100 win condition, and tie-breaker rules are copied verbatim into `duel-sync`.

## Caveats

- Existing local users (the JSON file) will not be migrated — they'll need to create accounts. Confirm this is acceptable.
- This is a large change (~2500-line `App.tsx` touched in many places). Expect one or two follow-up fixes after the first build.
